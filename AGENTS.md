# Project verification

- The open-source main release targets Minecraft 1.21.11. Publish only sanitized source and neutral artifacts; never publish deployment endpoints, credentials, live user databases, personalized jars, or private deployment/profiling tools. History cleanup and force-pushes require separate explicit approval. Leave other Minecraft-version lines unchanged unless explicitly requested.

- Run `gradlew.bat build` from `mod/` on Windows (or `./gradlew build` on Unix).
- Run `npm.cmd test` from `relay/` on Windows (`npm test` elsewhere); cut-routing tests execute the real server handlers in a VM with fake sockets and in-memory config, without contacting Discord or changing live users.
- `relay/wartable.test.js` checks admin-only edits, live delivery, login replay, persistence, cut visibility, and demotion to trial. Full War Table sync must filter per recipient just like incremental updates. Authoritative sync replaces the shared/cached stroke layer while preserving the separate `wartable-local-strokes.json` layer used by unauthenticated clients.
- `build` includes the standalone `snitchDimensionTest` and `apiContractTest` Java assertion runners; no JUnit dependency is used. Expected API-test logs include deliberate listener-failure and recursive-event-overflow cases.
- `build` also runs `cleanFontMetricsTest`, which bakes the bundled font atlas without a GPU and checks logical advance widths, spaces, cardinal labels, fallback measurement, transparent padding, mipmap coverage, fractional glyph placement, marker smoothing across distance-text updates, radar text scaling, and font pipeline registration.
- Run `gradlew.bat cleanFontShaderTest` on a graphical Windows session to compile/link both atlas-alpha and native-grayscale font shader variants against Minecraft's GUI vertex shader in a hidden OpenGL 3.3 context, and render/read back transparent, partial, and opaque coverage samples. This GPU check is separate from the headless `build` checks.
- `uiFontTest` verifies HUD-only font scoping (including nested/failed renders and deferred GUI text), custom-font preservation, the native FreeType loading path, Unicode fallbacks, shadow suppression, and mixin target signatures. Native clean text is limited to chat layout/rendering and its input field, actionbar notifications, titles/subtitles, OpenIntel armor/potion HUDs, and OpenIntel-owned map overlays; inventories, menus, and other mods retain their fonts. Changing `cleanFont` reflows chat without clearing history. Clean text has no shadows and uses a light four-sample antialiasing filter with one-eighth-pixel offsets.
- `/oi settings` → HUD → Text → Font switches between Clean font and Minecraft font immediately, saves `cleanFont`, and reflows existing chat. `uiFontTest` checks the toggle labels, both directions, and persistence/runtime wiring.
- Chat input uses a dedicated renderer that delegates to the original advance-validating glyph provider. Other text fields and the command-suggestion popup keep their original renderer. `uiFontTest` checks input widths, cursor positions, selection, scrolling, custom fonts, and toggle behavior.
- `radarLabelLayoutTest` checks clustered labels, plain compass rendering without backings or collision reservations, variable text heights, screen-edge clamping, stable ordering, and explicit overflow counts. It also checks full-rotation stability for pairs and eight-contact clusters, resize/reset handling, and absence of invisible overflow reservations. Placement history is keyed by contact identity and uses bounded, blip-relative row slots with hysteresis; labels never follow another label's moving edge. Radar player text is independent of icon size.
- Radar player rendering is local-only: Minecraft-loaded player entities within `radarRange`, with existing contact filters. Relay-only player blips and the relay-radar UI toggle are disabled; the legacy config field remains for compatibility and the API reports relay radar disabled. Shared pings and world/JourneyMap/Xaero intel remain unchanged. `radarLabelLayoutTest` verifies the local-only render path.
- Clean font layout/drawing iterates Unicode codepoints, not UTF-16 halves. Snitch feed prefixes use plain text instead of unsupported satellite pictographs; the atlas includes the death-marker cross. `cleanFontMetricsTest` checks supplementary-character fallback width, bounds, and emitted quad count.
- Native clean chat/UI glyph coverage is strengthened without changing metrics or adding shadows. `cleanFontShaderTest` validates the native contrast curve, unchanged custom-atlas coverage, and logo transparency/antialiasing at several physical sizes.
- `logoHudTest` verifies the O/eye assets and physical-pixel-aware bottom-right layout across resolutions and GUI scales. The HUD logo is 28–72 physical pixels (smaller only for tiny windows), hidden with F1/open screens, and toggleable under HUD → Elements. `logo.svg` and `icon.png` are the standalone artwork; the HUD uses the analytic `logo.fsh` shader. All visible logo pixels are black, both eye corners join the O, and only the edges vary in alpha for antialiasing. CPU connectivity and GPU monochrome tests guard this design.
- Clean font rendering submits one retained GUI element per text run, not per glyph. `cleanFontMetricsTest` verifies batched vertices, UV bounds, spacing, fractional geometry, and submission count. `uiFontTest` checks per-run style reuse and allocation-free atlas-prefix matching.
- For local JFR diagnostics, use `settings=none` with a narrow whitelist of sampling/GC/allocation events rather than capturing JVM arguments or environment variables. Ignore the first allocation-weight sample per thread when estimating allocation during the recording.
- `mapFontTest` verifies font scoping by overlay owner, deferred map labels, optional JourneyMap hook metadata, and the Xaero label-only scope. `gradlew.bat mapFontTest -PjourneyMapJar="<jar path>"` additionally checks the installed JourneyMap `BaseOverlayDrawStep.drawText`/`getModId` signatures without loading the mod. Only OpenIntel-owned map labels use the clean font; map-mod UI and other overlay owners do not.
- `hudLayoutTest` verifies zero-edge/center snapping, viewport fitting, relative anchoring, resize round trips, GUI-scaled viewport sizes, Unicode truncation, edge overflow, and shared editor bounds. Built-in HUDs persist a reference GUI viewport plus normalized anchors; resizing does not rewrite saved positions. Registered API HUDs retain their pixel-position/declared-size contract and uniformly fit only when oversized.
- `offlineIntelTest` verifies that snitch forwarding does not gate local detection, locally observed friend hits are retained, and snitches/pings keep separate local and relay provenance. Relay reconnects and `intel_reset` clear only received/shared state; Minecraft join/disconnect clears both sources and local dedupe state. Hidden local observations still expire, and remote echoes never become local evidence. Local feed entries survive relay-only clearing; the blanket notifications-cleared event is emitted only when the feed becomes empty.
- `relicMapNameTest` verifies relic labels prefer the first nonblank map lore line, discard formatting codes, and fall back to the item title or `Relic`.
- `warTableTest` checks projection/codec geometry, local-mode permissions, local-layer survival across authoritative sync, and invokes the actual screen raster painter without a Minecraft client or GPU. It covers incomplete/zero-length arrow drafts, visible shafts/arrowheads, repeated endpoints, line/arrow endpoint replacement, and coordinate/style-based draft cache invalidation. Its test-only screen allocation bypasses the vanilla constructor because it requires a running client.
- `gradlew.bat publishToMavenLocal` publishes the neutral remapped mod and sources for local Fabric integration development.
- API examples live in `README.md`; a compiling consumer example lives in `mod/src/test/java/example/ExampleOpenIntelIntegration.java`.
- Initialize the integration API on Fabric `ClientLifecycleEvents.CLIENT_STARTED`, not directly in `onInitializeClient`: Minecraft's executor thread identity is not ready during its constructor. The API contract test checks this startup hook.
- Never publish personalized jars or relay credentials as development dependencies. Keep `openintel_token.txt` set to `CHANGE_ME` in source/base builds. `publicationSafetyTest` verifies the placeholder token, blank client endpoint defaults, and packaged font license notices.
- Read `mod_version` from `mod/gradle.properties` when selecting artifacts; older jars can remain in `mod/build/libs/` after a version bump. The public release is 1.7.0; the integration API major version remains 1.
